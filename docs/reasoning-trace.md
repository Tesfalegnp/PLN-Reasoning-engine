# Reasoning Trace and Explainability Specification

This document details the explainability and reasoning trace generation of the MeTTa PLN reasoning system.

---

## 1. Trace Design & Philosophical Principles

In symbolic AI and cognitive architectures, an explanation cannot be a post-hoc rationalization generated by an external language model. It must be a **faithful reflection of the actual deductive unification steps** performed by the reasoning engine.

In our system:
1. Every proof is constructed **natively in MeTTa** during unification:
   - Base grounding facts emit: `(Fact <Statement>)`
   - Initial premises emit: `(Initial <Statement>)`
   - Inference rules emit: `(Rule <RuleIdentifier> <SubProof1> <SubProof2>)`
2. The complete tree is bundled into a `Proof` atom:
   ```lisp
   (Proof (⊢ <Conclusion> (stv <Strength> <Confidence>)) <ProofTree>)
   ```
3. The Python integration layer parses this recursive AST without altering its semantics, allowing both hierarchical tree rendering and formatted step-by-step resolution traces.
